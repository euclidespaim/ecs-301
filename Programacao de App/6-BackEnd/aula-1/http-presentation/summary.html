1. Teoria de Comunicação HTTP

O HTTP (Hypertext Transfer Protocol) é o protocolo de comunicação padrão da Web, estruturado no modelo de Requisição e Resposta. O cliente (navegador/aplicação) inicia o contato enviando uma mensagem de solicitação contendo uma URL (recurso de destino) e um Método HTTP (ou verbo), especificando qual ação semântica deseja aplicar sobre o recurso. O servidor processa a requisição e retorna uma resposta com um código de status (ex: 200 OK, 201 Created).

2. Propriedades Semânticas Fundamentais

Para arquitetar APIs RESTful robustas, os métodos devem aderir a duas propriedades importantes:

  • Métodos Seguros (Safe): Ações exclusivas de leitura. Não alteram o estado do recurso no servidor nem produzem efeitos colaterais. Podem ser cacheados com segurança (ex: GET, HEAD, OPTIONS).
  • Métodos Idempotentes: Múltiplas execuções idênticas e consecutivas da mesma requisição deixam o servidor exatamente no mesmo estado que uma única execução. Previne erros de duplicação em instabilidades de rede (ex: GET, PUT, DELETE).

* Entendendo a Idempotência na prática: É como o botão de chamada de um elevador: apertá-lo 1 ou 10 vezes tem o mesmo resultado final (o elevador vem uma só vez). Em APIs, se a rede oscilar ao enviar uma exclusão (DELETE) ou substituição (PUT), reenviar a requisição é seguro. Com POST (não-idempotente), isso geraria duplicatas.

4. Definições dos Métodos Principais (CRUD)

GET

Leitura: Recupera o recurso solicitado. Parâmetros são expostos na URL via Query String. Não altera estado do servidor.

GET /usuarios?ordenacao=nome HTTP/1.1
POST

Criação: Envia dados no corpo para criar um novo registro. Não seguro e não idempotente (duplo clique gera duplicados).

POST /usuarios HTTP/1.1 (body: JSON)
PUT

Substituição Integral: Atualiza completamente um recurso. Campos omitidos serão removidos ou resetados no servidor.

PUT /usuarios/1 HTTP/1.1 (body: JSON)
PATCH

Atualização Parcial: Altera apenas os atributos específicos fornecidos no corpo da requisição, preservando os demais.

PATCH /usuarios/1 HTTP/1.1 (body: JSON)
DELETE

Exclusão: Remove o recurso. Idempotente: uma vez deletado, permanece deletado. Chamadas subsequentes costumam retornar 404 (Não Encontrado), mantendo a idempotência (estado final do servidor não muda).

DELETE /usuarios/1 HTTP/1.1

5. Métodos Auxiliares, Diagnóstico e Infraestrutura

HEAD OPTIONS

HEAD: Mesmos cabeçalhos do GET, mas sem corpo. Valida metadados (tamanho, tipo).
OPTIONS: Obtém cabeçalhos de controle e verbos permitidos. Essencial para CORS Preflight.

CONNECT TRACE

CONNECT: Estabelece túnel TCP/IP direto, permitindo HTTPS criptografado através de proxies.
TRACE: Retorna de loopback a requisição recebida, auditando modificações de cabeçalho.

6. Anatomia de uma Transação HTTP (Exemplo Cru)

Requisição (Cliente → Servidor)

POST /usuarios HTTP/1.1
Host: api.exemplo.com
Content-Type: application/json
Content-Length: 31

{"nome":"Pedro","cargo":"Dev"}

Resposta (Servidor → Cliente)

HTTP/1.1 201 Created
Content-Type: application/json
Content-Length: 41

{"id":4,"nome":"Pedro","cargo":"Dev"}

7. Códigos de Status HTTP Comuns

2xx Sucesso (Success)

• 200 OK: Sucesso padrão. Comum em GET, PUT e PATCH.

• 201 Created: Recurso criado com sucesso. Resposta do POST.

• 204 No Content: Sucesso, sem corpo (ex: DELETE e OPTIONS).

4xx & 5xx Erros (Errors)

• 400 Bad Request: Requisição inválida (corpo ou parâmetros incorretos).

• 404 Not Found: Recurso ou rota não encontrada no servidor.

• 500 Internal Server Error: Erro interno crítico do servidor.
