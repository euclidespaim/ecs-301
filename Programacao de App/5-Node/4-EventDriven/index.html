Parte 1: O Paradigma

Entendendo como o Node.js "pensa".

O que é um Evento?

Ocorrência

Qualquer ação reconhecida pelo software, como um clique ou um erro no sistema.

Assíncrono

Eventos acontecem a qualquer momento, sem seguir uma linha reta obrigatória.

Resposta

O software "ouve" a ocorrência e dispara uma função para tratá-la imediatamente.

Modelos de Programação

Sequencial

Executa instruções de cima para baixo. Cada tarefa deve terminar para a próxima começar. É rígido e previsível.

Orientado a Eventos

O fluxo é determinado por triggers externos. O programa "espera" e "reage" de forma dinâmica.

Por que o Node.js é rápido?

Diferente de tecnologias antigas, o Node.js não fica "parado" esperando o banco de dados ou um arquivo carregar.

Através do Event Loop, ele delega a tarefa e continua processando outras requisições. Quando a tarefa termina, um evento avisa: "Estou pronto!".

Eficiência máxima de CPU e memória.

Parte 2: EventEmitter

A ferramenta central para criar eventos.

A Analogia do Alarme

Pense no EventEmitter como a central de um alarme residencial.

A central não sabe quando a janela será aberta, mas ela tem um sensor (ouvinte) pronto para tocar a sirene (ação) no momento da invasão (evento).

Central de Controle

Os 3 Passos Fundamentais

1. Preparar

Importar o módulo events e criar a nossa "central" (emissor).

2. Ouvir

Definir o que o sistema deve fazer quando o evento X ocorrer.

3. Disparar

Apertar o gatilho manualmente para executar a reação programada.

Passo 1: Importar o Módulo

Tudo começa com a importação da classe nativa do Node.js.

const events = require('events');

Esta variável agora contém todo o poder necessário para gerenciar fluxos de dados.

Passo 2: Criar o Emissor

01

Instanciar a Central

Criamos um objeto que será o responsável por emitir e ouvir os sinais.

const emissor = new events.EventEmitter();

Passo 3: O Ouvinte (.on)

O método .on() é o sensor. Ele fica "escutando" um nome específico de evento.

emissor.on('fogo', () => {
  console.log('🚨 Água ativada!');
});

Monitorando canal...

Disparando a Ação (.emit)

Gatilho

O comando emit avisa a todos que o evento ocorreu.

Dados

Você pode enviar informações extras junto com o disparo do evento.

emissor.emit('fogo');

Imediatamente, a função vinculada ao 'fogo' começa a rodar.

Parte 4: Dominando Recursos

Gerenciando ouvintes e memória do sistema.

Ouvir apenas uma vez (.once)

Método .on()

O ouvinte continua ativo por tempo indeterminado. Toda vez que o evento for disparado, a função roda novamente.

Método .once()

O ouvinte é de disparo único. Ele executa a função correspondente apenas na primeira ocorrência e se auto-destrói.

Múltiplos Ouvintes

Um único evento pode disparar uma cadeia de ações paralelas sem que um script interfira no outro:

emissor.on('venda', emitirNotaFiscal);
emissor.on('venda', atualizarEstoque);
emissor.on('venda', dispararEmailMarketing);

Modularidade completa: cada função cuida estritamente do seu escopo.

Tratamento de Erros ('error')

No Node.js, o evento chamado 'error' possui comportamento especial da arquitetura.

Se a aplicação emitir um erro e não houver um ouvinte programado para capturá-lo, o Node **derruba o processo imediatamente**.

emissor.on('error', (err) => {
  console.log('Capturado: ' + err.message);
});

Removendo Ouvintes (.off)

00

Desconectar Sensores

Podemos desligar ouvintes específicos em tempo de execução para evitar consumo desnecessário de memória da VPS.

emissor.off('alarme', tocarSirene);
