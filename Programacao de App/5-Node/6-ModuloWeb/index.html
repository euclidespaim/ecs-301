Parte 1: O que é um Servidor Web?

Compreendendo como sistemas distribuídos se conversam na arquitetura de rede.

O Conceito de Servidor

O Servidor Físico (Hardware)

É um computador físico montado em um rack de datacenter. Ele tem processador, memória RAM e armazenamento, mas não possui monitor ou teclado conectados diretamente.

O Servidor de Software (Serviço)

É o programa que nós criamos usando Node.js. Ele fica rodando na máquina invisivelmente, escutando uma porta específica de rede e devolvendo dados quando alguém chama.

A Arquitetura em 4 Camadas

1

Cliente

O navegador web que faz o pedido visual na tela.

2

Servidor Web

O Node.js recebendo a conexão de rede pura.

3

As regras de negócio que nós programamos por trás.

4

Os arquivos e bancos de dados salvos para sempre.

Parte 2: O Módulo HTTP

Entendendo a dinâmica clássica de envio de cartas na internet.

A Metáfora da Carta (HTTP)

Ciclo Fechado: Envio e Resposta

O protocolo HTTP funciona exatamente como enviar uma carta tradicional pelos Correios. O cliente envia uma requisição (Request), o servidor lê, processa, joga a resposta de volta (Response) e fecha a conexão imediatamente.

O servidor não sabe quem você é depois que a resposta foi entregue. É um modelo sem estado fixo (Stateless).

Conexão Temporária

O canal de comunicação se destrói assim que os arquivos terminam de carregar.

Código Prático: Servidor de Arquivos

Combinando o módulo http com o módulo fs para entregar uma página HTML real:

const http = require('http');
const fs = require('fs');

http.createServer((req, res) => {
    // Busca o arquivo físico na pasta
    fs.readFile('pagina.html', 'utf-8', (err, dados) => {
        if (err) {
            res.writeHead(404, {'Content-Type': 'text/plain; charset=utf-8'});
            return res.end('Página não encontrada! ❌');
        }
        res.writeHead(200, {'Content-Type': 'text/html; charset=utf-8'});
        res.end(dados); // Entrega o HTML renderizado!
    });
}).listen(8080, () => {
    console.log('Servidor HTTP rodando em http://localhost:8080');
});

Parte 3: Sockets e TCP

Conexões persistentes e canais de dados abertos em tempo real.

A Metáfora do Walkie-Talkie

Canal Aberto em Tempo Real

Diferente do HTTP, o modelo de Sockets TCP funciona como um Walkie-Talkie ou uma ligação telefônica ativa. Os computadores se plugam na rede e o cano de comunicação continua aberto por tempo indeterminado.

Qualquer um dos lados pode enviar dados a qualquer momento sem precisar pedir permissão de novo. É a base de jogos online e chats de mensagens rápidos.

Fluxo Contínuo

Comunicação Bidirecional (Full-Duplex) ativa até que alguém decida desligar a tomada.

Por que usamos o TCP?

O protocolo TCP (Transmission Control Protocol) garante a confiabilidade absoluta da entrega:

  • Sem perdas: Se um pedaço do dado cair no caminho, o protocolo pede para reenviar automaticamente.
  • Ordem Correta: Os pacotes de informação chegam e são organizados exatamente na ordem em que foram enviados.
  • Aperto de Mão: Antes de enviar o primeiro caractere, ele faz o "Handshake" para garantir que o outro lado está pronto para ouvir.

Código Prático: Servidor TCP

Criando um servidor de rede puro com o módulo nativo net do Node.js:

const net = require('net');

// Toda nova conexão de cliente cria um objeto 'socket' diferente
const servidor = net.createServer((socket) => {
    console.log('🔌 Um cliente acabou de se conectar na nossa tomada!');

    // Fica escutando as mensagens que chegam desse cano de dados
    socket.on('data', (dados) => {
        console.log('Recebido do cliente: ' + dados.toString());
        socket.write('Servidor diz: Recebi seu texto! -> ' + dados);
    });
});

servidor.listen(3000, () => {
    console.log('🚀 Servidor TCP escutando na porta 3000');
});

Código Prático: Cliente TCP

O script que vai rodar no terminal do segundo computador para se conectar ao servidor:

const net = require('net');

// Conecta direto na máquina do colega usando o IP ou localhost
const cliente = net.createConnection({ port: 3000 }, () => {
    console.log('✅ Conectado com sucesso ao servidor TCP!');
    cliente.write('Olá! Esta mensagem veio do computador da dupla 301!');
});

// Ouve o que o servidor mandar de volta
cliente.on('data', (dados) => {
    console.log('Mensagem do Servidor: ' + dados.toString());
    cliente.end(); // Fecha o cano ao terminar
});

Parte 4: Desafio Prático

Colocando os computadores do laboratório para conversarem entre si.

Desafio Prático: Chat de Terminal

Hackers da Rede:

  1. Trabalhem na mesma bancada de computadores. O Computador A será o Servidor e o Computador B será o Cliente.
  2. No Computador A, rode o arquivo do Servidor TCP na porta 3000. Descubra o IP da máquina usando o comando ipconfig ou ifconfig no console.
  3. No Computador B, altere o código do Cliente TCP para apontar para o IP do computador A (Ex: host: '10.90.x.x', port: 3000).
  4. Execute os scripts simultaneamente e veja a conversa acontecer em tempo real direto pelas janelas pretas do terminal do VS Code!
